# intent_MILEAGE — правило «пробег не больше 400 000 км, иначе review»

## Замысел

Добавить в расчёт решения по заявке проверку пробега: пробег авто не больше
400 000 км — решение определяется остальными критериями как раньше; при пробеге
больше 400 000 км решение — `review`, даже если по остальным критериям заявка
получила бы `approve` или `reject`. Правило относится к расчёту решения, а не к
проверке входных данных. (исходная формулировка — интервью; перекрытие `reject` —
ответ в интервью, вопрос 1; значения `approve`/`review`/`reject` — код:
backend/src/Domain/DecisionEngine.php)

## Зачем

Сегодня решение по заявке не зависит от пробега: после проверки входных данных
пробег не участвует ни в решении, ни в лимите — две заявки, различающиеся только
пробегом, получают одинаковое решение (код: backend/src/Domain/AssessmentService.php).
Изменение закрывает этот пробел: решение начинает учитывать пробег (исходная
формулировка — интервью). Бизнес-мотивация порога не прозвучала — вынесена в
Open questions.

## Constraints

- При пробеге больше 400 000 км решение — `review`; при 400 000 км и меньше —
  решение по остальным критериям. (ответ в интервью — исходная формулировка)
- Превышение перекрывает любое решение по остальным критериям: заявка, которая
  без правила получила бы `reject`, при перепробеге получает `review`.
  (ответ в интервью — вопрос 1)
- Граница включительная: ровно 400 000 км — допустимый пробег, `review` начинается
  с 400 001 км. (ответ в интервью — вопрос 2)
- Неуказанный пробег (поле отсутствует или null) отклоняется как невалидный с
  HTTP 422 — поведение не меняется. (ответ в интервью — вопрос 3; код:
  backend/src/Domain/ApplicationValidator.php, код:
  backend/src/Http/ApplicationController.php)
- Пустое значение поля пробега трактуется как 0 и даёт решение по остальным
  критериям; пустое поле формы уходит в API как 0. (ответ в интервью — вопрос 3;
  код: backend/src/Domain/ApplicationValidator.php, код: frontend/app.js)
- Валидационная граница пробега не меняется: валидны 0–500 000 км; пробег
  400 001–500 000 км — валидный вход, дающий `review`; больше 500 000 км —
  ошибка валидации. (ответ в интервью — вопрос 4; код: backend/config/rules.php,
  код: backend/src/Domain/ApplicationValidator.php)
- Решение по остальным критериям не меняется: LTV меньше 60 — `approve`,
  60–85 — `review`, больше 85 — `reject`. (код:
  backend/src/Domain/DecisionEngine.php, код: backend/config/rules.php)
- Лимит не меняется: запрошенная сумма при `approve`, 0 — при `review` и `reject`.
  (код: backend/src/Domain/AssessmentService.php)

## Не входит

- Подсказка в форме при вводе пробега больше 400 000 км. (ответ в интервью — вопрос 5)

  backend/src/Domain/DecisionEngine.php)
- Изменение валидации пробега: границы 0–500 000 км, поведение при неуказанном
  или пустом значении, тексты ошибок. (ответ в интервью — вопросы 3 и 4)
